Lower-severity defects from the finders' notes

Each finder was asked for its ten best findings; these are the rest, as the finders described

them. None was independently verified.

archives

  • core:zip never checks the local-header name against the central-directory name, and a duplicate name always resolves to the first entry, a parser differential that can bypass name-based validation.
  • json.stringify passes non-UTF-8 bytes through and can emit a document its own parser rejects.
  • tycho-ar c follows symlinks, archiving targets outside the directory as regular files, and a self-referential symlink makes it die; neither is documented.
  • docs/reference/corelib.md (line 709 at b9df4aa) omits the TooBig variant of ZErr.

codegen

  • tychoc1 refuses the spec builtin pow(x, y) with a location-less internal error because emit.ty has no pow case.
  • In tychoc, a user fn named __lam0 collides with the first lambda's generated symbol and the C build fails.
  • tychoc1 reports a closure local that shadows a same-named fn as unused.
  • Cross-package mangling collisions are refused in both compilers with a misleading same-package diagnostic that names the mangled symbol.
  • The unknown-procedure hint for abs points at core:bignum instead of core:math, depending on readdir order.
  • str() of an imported or generic struct prints the mangled type name.
  • String literals are emitted without escaping '?', so under -std=c11, which several repo scripts use, trigraphs corrupt the string.
  • ASan does not flag the arena free-list corruption because the arena manages its own memory.

db

  • tycho-db accepts a CREATE TABLE with a duplicate column name; the second column can never be reached, whereas sqlite refuses it.
  • The tycho-db CLI parses flags with the lax strings.parse_int, so malformed port and hook values silently bind wrong or random ports or disable the hook.
  • The CLI ignores extra positional arguments, and a directory given as the script runs nothing and exits 0.
  • MAX_LINE is soft: statements of 8193-12287 bytes still execute, and on TooLong the peer gets a TCP reset with no in-band error.
  • The lex error for a non-ASCII byte echoes a single byte of a UTF-8 sequence, putting invalid UTF-8 on stdout and the wire.
  • tychoc emits two 'is copied into this aggregate' warnings for exec.ty that tychoc1 does not (warning parity gap).

net

  • Unreproduced suspicion: tls_shim.c tcp_connect_timed casts the millisecond timeout to int for poll() with no INT_MAX bound, reachable only through the package-private tls._connect_timeout.
  • Unexercised suspicion: http_shim.c formats the content type into a 512-byte buffer, so a longer value would be silently truncated.

parity

  • Both compilers run out of memory on polymorphic recursion at a doubling type because the 1024-instance cap never fires.
  • reserve(xs, -1) is a no-op in both compilers instead of aborting as the spec requires for a negative capacity.
  • tychoc1 refuses literal adaptation in send(c, 3) on sized channels that tychoc accepts, the method form skips the range check, and the diagnostic prints internal type spellings.
  • The range diagnostic for a u64 literal prints the int range instead of the u64 range.
  • t.0.0 fails in both compilers because 0.0 lexes as a float.
  • A const used as a binary operand with a sized operand compiles in tychoc but is refused by tychoc1.
  • Smaller parity gaps exist on nested subscript assignment, inout on a map element, and field access through a struct newtype.
  • exit(256) exits with status 0 in both compilers, while the spec says exit terminates with status code.

program

  • A default tychoc1 build of the app gets a gcc -Wstringop-overread warning from tycho_str_concat3; tychoc is silent, and the emit-warn lane cannot see this class.
  • json.TooDeep always reports byte 0, contrary to docs saying every refusal carries the offending offset.
  • A comment in json.ty for JFloat references a header section that does not exist.
