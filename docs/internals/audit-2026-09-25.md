# Defect hunt, 2026-09-25

A session aimed at finding defects nobody had recorded, after the open list in
[FRICTION.md](FRICTION.md) was closed on 2026-08-18. Host: linux-x86_64,
Ubuntu 24.04, gcc 13.3, 4 cores. Baseline: `b9df4aa`. **Nothing in this record is fixed yet.**
Every entry below is a defect in that commit, with where it lives and how it was reproduced;
the repro programs themselves lived in a scratch directory that did not survive the session.

Method: eleven finder agents, each on one surface (compiler CLI, generated-source scale,
compiler parity, emitted C, runtime, shims, the FFI surface, the network stack, tycho-db,
archive and text parsers, and a real 1000-line program). Each finding was then handed to a
separate verifier told to refute it: re-run it, check it against FRICTION, the spec and the
reference, minimise it, and locate the cause. "verified" below means it survived that;
"unverified" means a finder reproduced it but the session ended before a verifier ran;
"reproduced" means found and reproduced by hand during the session.

Totals: 90 defects -- 3 reproduced, 25 unverified, 62 verified; by severity 2 critical, 18 high, 47 medium, 23 low.

## What was done

- **Build prerequisites installed and recorded.** `gcc-multilib` (the ilp32 lane refuses to
  skip), `libcurl4-openssl-dev` (`core:http`), and `locales` with `locale-gen da_DK.UTF-8`.
  Without the last one `make test` fails `float_lit_locale` and `float_str_locale`, exactly as
  FRICTION #111 says. wine is absent, so its lanes skip. `make preflight` is green after these.
- **Baseline `make ci` run twice on the untouched tree.** The first stopped at `make test`,
  whose only failures were the two locale fixtures. The second, with the locale installed, was red in `make debug-check`
  (D90) and in nothing else that reported; the sweep was stopped during the four-lane join,
  before the fuzz lanes, so it is not a full verdict.
- **Parity fuzzers run by hand on the baseline:** eq-parity 512/512, unary-parity 30/30,
  parfor-parity 25/25, type-parity 4608/4608 -- all match their oracles. `fuzz/run_pkg.py 2000`
  was at 1000/2000 with 0 FAIL when it was stopped.
- **Eleven finder lanes run to completion; eight fully verified** (runtime, shims, FFI surface,
  network, tycho-db, archives, the 1000-line program, CLI). The scale lane is 6 of 11 verified;
  the parity and codegen lanes returned 10 findings each, but their verifiers had not run when
  the session ended. Those 25 are the "unverified" rows.
- **The 1000-line program was written and run** (an HTTP JSON key-value and job-queue service:
  `core:httpd`/`json`/`io`/`sqlite`/`signal`, five packages, a `select` actor, a `parallel for`
  worker pool, generics, `or_return`/`or_else`). It builds and runs under both compilers once
  D81 is worked around; its walls are the "Found by the 1000-line program" rows.
- **Fix work was started and stopped.** Fixer agents began on eleven groups of these defects
  in private clones; none had committed when the session was wound up, and none of that work
  is in the tree.

### D01. Assigning to an element whose container the right-hand side grows through 'inout' writes into a buffer the arena has already recycled: free-list corruption and SIGSEGV (tychoc1+gcc, tychoc+clang), or a lost update (map, both compilers+gcc)

- **Where:** Place-store lowering. tychoc1: compiler/emit/emit.ty emits '(*tycho_arr_int_ptr(&(h_xs), 0LL)) = h_grow(_parent, &(h_xs), &_scope);'. Both compilers emit '(*tycho_map_si_slotptr(&_scope, &(h_m), TYCHO_LIT("x"))) = h_fill(...)' for a map place. tychoc emits ...
- **Observed:** f_place_inout_uaf/main.ty: fn grow(a: inout [int]) -> int: push(a, 0) return 7 fn main(): xs := [1, 2, 3] xs[0] = grow(&xs) ys := [4, 5, 6] zs := [7, 8, 9] println(str(xs[0]) + " " + str(ys[0]) + " " + str(zs[0])) == tychoc -> '7 4 7' rc=0 == tychoc1 -> 'Segmentation fault $S/f_place_inout_uaf/$c' rc=139 gdb: '760 FreeNode *fn = a->bkt[k]; a->bkt[k] = fn->next;' ... '#3 tycho_arr_int_with_cap ...
- **Mechanism:** The store is emitted as '*ADDR(place) = RHS' or 'set(&*ADDR(outer), i, RHS)'. The address computation and the RHS call are unsequenced (indeterminately sequenced) C operands or arguments. gcc computes 'tycho_arr_int_ptr'/'slotptr' first, and clang computes set()'s first argument first. The RHS's inout push reallocates and calls arena_recycle on the old block, so the store writes the Tycho value into a FreeNode's 'next' field. The next same-size allocation then pops that value as a pointer. With a map, the table is rehashed and the write goes to the dead table, so the update is lost.
- **Suggested fix:** In both emitters, when a place-store's RHS contains any call (or at least an inout argument rooted at the place's root variable), evaluate the index legs into temps first (as §13.4 requires), then the RHS into a temp, and only then compute the element address and store: '{ tycho_int _i = idx; T _v = rhs; *tycho_arr_int_ptr(&xs, _i) = _v; }'. The same applies to map slotptr and nested ptr chains. ...
